01

The weight: a magnetic state, read as a conductance

In a magnetic tunnel junction, two magnetic layers sandwich a barrier thin enough to tunnel through. When their magnetisations point the same way the device conducts comparatively well; when they oppose, it conducts less. Nothing is stored as charge. The stored value is an orientation, it survives the power being cut, and the circuit reads it as a conductance.

A domain-wall device is the same idea with a position instead of an orientation. A wall sits somewhere along a track, pinned at defects, and how much of the track is magnetised one way sets the conductance — so it holds more than two distinguishable states. They are one model with a knob, states per device, rather than two separate machines. That is why this repository builds one crossbar and parameterises it.

Two devices make one weight here. A conductance cannot be negative, so a signed weight needs a scheme, and this one wires a pair so their currents subtract. It costs twice the devices and buys twice the signed range out of a conductance window that is the platform's binding constraint — two independent error draws raise the noise by √2 against a range that doubles, a net √2 in signal-to-noise, before counting the baseline current an offset scheme would have to subtract downstream.

02

The sum: Kirchhoff's law does the arithmetic

Arrange the devices in a grid. Drive each row with a voltage, and each device passes a current set by its own conductance — Ohm's law, once per device. Every device on a column empties into the same wire, and the wire adds them, because that is what a wire does.

That is the whole multiply–accumulate. A 36×10 matrix–vector product costs one settling time and no instructions: there is no loop, no accumulator register, and no clock inside the array. What the hardware computes is not an approximation of the arithmetic; the arithmetic is a description of what the hardware does.

The multiply–accumulate is linear. Whatever nonlinearity a network needs has to sit in the periphery — in the sense amplifier, the converter, and whatever follows them. That is a real difference from an optical network, where a detector measures intensity and supplies a square-law nonlinearity for free. This project intends to characterise the difference rather than argue from it.

03

The task: thirty-six pixels, and your handwriting

The machine learning here is deliberately minimal, and stays that way. The task is MNIST at 6×6 — 36 inputs, ten columns, one linear map, trained with sixty epochs of plain gradient descent in NumPy. No hidden layer, no convolution, no autograd: the gradient of softmax cross-entropy through one matrix is Xᵀ (p − Y), and importing the largest dependency in the ecosystem to avoid writing that line down would be a poor trade.

Small is the point. All of this project's complexity belongs in the device physics and the error model, and a task that is understood completely is the only kind against which a tolerance means anything. An accuracy that fell because the network was fragile would tell you nothing about the hardware.

The test set is imported from the first platform as data, not regenerated. That is the one deliberate exception to keeping these repositories independent, and it exists because independently regenerating “the same” MNIST subset is exactly how two platforms end up scored on different data without anyone noticing. 36 channels is also what makes the comparison like for like: a crossbar is an N×N matrix engine, so an interferometer mesh is its counterpart, not a diffractive stack.

An ideal array gets 0.7345 of the 2,000 held-out digits right. Not 99% — there are thirty-six pixels and no hidden layer. That number is the ceiling everything below this point is measured against.

Watching a 4 turn into nine grey squares explains more about that than a paragraph can.

04

The seam: Python designs, MATLAB measures, nothing crosses back

Everything above describes an ideal array: exact conductances, infinitely resolvable states, perfect wires. It is written in Python and it is the design. The as-built model — the device error, the Monte Carlo, the tolerance budget — is written in MATLAB, and the two are joined by a single HDF5 file that travels one way only.

That direction is the point. A design that can be quietly adjusted to flatter its own error budget is not a measurement of anything. So there is one writer and one reader on each side, the operating point is a closed set of five keys — g_min_s, g_max_s, read_voltage_v, readout_gain, signed_scheme_code — and both sides refuse an unknown key and a missing required one. Neither reader supplies a default, because a default is indistinguishable from a correct value downstream: it turns a renamed field into a plausible wrong answer instead of a stack trace.

states_per_device deliberately does not cross. How many levels a device resolves is a property of what was built, not of what was designed, so it belongs to the error config on the far side of the seam.

The seam is proven by round trip: MATLAB rebuilds the array from the file alone and has to reproduce the accuracy Python recorded. That is the only detector for a transposed weight matrix, a column-major image flatten, an assumed signed scheme or a defaulted gain — none of which raise an error, and all of which return a plausible number.

What the round trip caught

Quantisation was first implemented on each device independently, which is the obvious reading of “devices are what have finite states”. With two-state devices and a target weight of 0.3, the positive rail rounds up and the negative rounds down, and the pair lands on +1 where the nearest representable weight is 0. The differential pair collapses to a sign bit, at twice the device count of an offset scheme — every argument for choosing it, voided, silently. The only symptom was a lattice with two values in it where a probe expected three. Quantisation now applies to the effective weight, over the set a legal combination of device states can reach, on both sides.

A second trap surfaced while fixing the first: NumPy rounds half to even and MATLAB rounds half away from zero. They differ only on exact halves — which is precisely where a weight sits between two device states. Left alone, the two sides would have quantised such a weight differently, agreed on everything else, and disagreed on an accuracy by a sample or two with nothing to point at. Both sides now round away from zero, and so does the JavaScript on this page.

05

Building it badly: what device error does to the answer

Three error sources, chosen because they are what a crossbar actually suffers from rather than because the other platform had a list of that length. Forcing a common list onto both would measure the taxonomy instead of the hardware.

Conductance variation is the spread between the state a device was programmed to and the state it holds. Every device gets its own draw, which under a differential pair is two draws per weight, and the result is clamped at the window edges — a device cannot be programmed outside the states it has. It is quoted as a fraction of the conductance window, which is what lets it convert straight into the comparison unit.

Resolvable states is the knob from section 01, applied as an error rather than as a design choice. IR drop is the crossbar's own characteristic failure and has no photonic counterpart: the wires are not ideal conductors, so a cell far from both edges is starved of the voltage the driver thinks it is delivering. It is a systematic, not a random draw, it depends on where in the array a device sits, and it grows with array size.

Two things the panels cannot draw

IR drop is deliberately not converted to bits. It is a position-dependent systematic, not a spread on a stored value, so log₂(range / σ) has no σ to take, and forcing it into the unit would be a category error. Its bracket is also conditional twice over: on the array size, because the drop grows with it, and on the conductance window, because a wire drop is R·I and the current depends on the absolute conductance of the devices. Sources 1 and 2 cancel that window exactly; source 3 cannot, and the window is UNSOURCED.

Budgeting each source to its own edge leaves nothing over. All three at the last magnitude that individually held give 0.6819 ± 0.0119, which is under the pass mark. The joint drop is sub-additive rather than additive — a property of accuracy as a metric, since a digit already misclassified by one source cannot be misclassified again by the next, and no conclusion is drawn from it. What it means practically is that a design meeting all three at once needs each of them comfortably inside its bracket.

What the holes are, and why they stay holes

Spintronic device parameters are spread across a literature that mixes measurements with roadmap projections, and no distribution has been read into this repository yet. So g_min, g_max, the read voltage and the wire resistance are placeholders, marked as such everywhere they appear. No margin is claimed against an uncited value, and the margin column is omitted rather than estimated. A confident wrong number costs more than an admitted hole.

The accuracy and the bit depths do not depend on those placeholders — the window and the drive cancel exactly in the decode, and a test asserts the ideal accuracy is unchanged across unrelated windows. The energy figure does, so the arithmetic is given rather than the conclusion. Array read power is 1.577 µW, computed as meanₙ(Σᵢⱼ Vᵢ² Gᵢⱼ) over all 720 devices, and it is array only: it excludes the sense amplifiers, the converter and every digital stage after them, and the periphery frequently dominates an analog accelerator's energy. Energy per inference needs a read time on top of that, and no read time has been sourced — so multiply by whichever one a source supports.

08

Next: what is not built, and what it would take

The comparable core is complete and the row is reported. What follows is not missing — it is the work this result makes worth doing, in roughly the order that would pay.

  • Source the window g_max/g_min is the platform's characteristic constraint and it is currently a placeholder. It is the largest open gap: a cited distribution would turn the delivered-precision hole into a number and give the row its margin column.
  • Source a wire resistance IR drop's cliff is sharp — 100 Ω holds and 1 kΩ is chance — so a sourced value decides between “irrelevant” and “fatal” with very little in between at this array size.
  • Sweep the array size IR drop grows with the array, so the number above is one point on a curve. The size is fixed and stated first for exactly that reason; the curve is the obvious next measurement.
  • Solve IR drop self-consistently The present model is first order: the drops are computed from the currents the ideal voltages would draw, so one pass overstates them. That is the safe direction for a tolerance study and it is not the same as being right. Iterating is the refinement, and it matters most if this source turns out to bind.
  • Error sources 4 to 7 Sneak paths, read noise, converter quantisation and retention drift, in that order. The first three sources bound the design today; these decide whether that bound is the real one.
  • The spin-torque oscillator Complementary and explanatory, and it stays out of the comparison table on purpose — “how precisely must this be built to classify MNIST” is not a question you ask of a reservoir. Keeping it out is a decision, not an oversight, and it would need its own question before it earns a page.
